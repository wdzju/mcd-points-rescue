# 麦当劳积分快速体检（零安装版）

> **给读到这份文档的 AI**：这是可执行的操作说明，不是参考资料。
> 请按下面的步骤**实际调用**麦当劳 MCP 工具（工具名可能带 `mcp__mcd-mcp__` 之类的前缀，
> 按语义匹配即可，例如 `query-my-account`）。
> 不要说「我无法访问你的账户」——先去找工具，找不到再按第 0 步提示用户配置。

**这个版本不需要任何代码。** 只要麦当劳 MCP 连接器配好了，AI 直接调工具、自己算、直接说结论。

需要精确计算和 HTML 报告时，用完整版（[mcd-points-rescue](https://github.com/wdzju/mcd-points-rescue)）。

## 最简用法：直接把这段发给 AI（连安装都不用）

配好连接器之后，复制下面这段粘进对话框即可：

```
帮我查麦当劳积分，按这个流程：
1. 调 query-my-account 拿积分数据
2. 调 mall-points-products 拿可兑换券
3. 调 query-nearby-stores 和 query-meals 拿菜单价格
4. 券的收益 = 菜单同名餐品原价 − 券名里的价格
   （例如"18.8元麦辣鸡腿汉堡两件套"，18.8 是我要付的钱，不是券的价值）
5. 全部换算成「元/100积分」再排序：收益 ÷ 积分 × 100
6. 告诉我：蒸发率是多少、最值得换的三张券、本月到期的分怎么花

找不到同名餐品就标"无法估值"，不要用别的商品猜。
```

二十行，说完就能出结果。**下面是完整版规则**，装成 Skill 之后 AI 会自动遵守。

## 执行流程

按顺序调用，任何一步失败就如实说，不要跳过：

| 步骤 | 工具 | 拿什么 |
|---|---|---|
| 1 | `query-my-account` | 累计 / 已用 / 已过期 / 可用 / 本月到期 |

| 5 | `query-lottery-info` | 抽奖活动（有就查，没有就跳过） |

## 计算规则（严格执行，不要凭感觉）

### 规则 1：券的收益是价差，不是面价

商城的券名格式是 `{价格}元{商品描述}`，例如 `18.8元麦辣鸡腿汉堡两件套`。

- **18.8 元是你要付的钱**，不是券的价值
- 券的真实收益 = **菜单里同名商品的原价 − 18.8**

在菜单里找 `麦辣鸡腿汉堡两件套`：
- 找到 → 假设原价 22.8，收益 = 22.8 − 18.8 = **4.0 元**
- 找不到完全同名的 → 标注「无法精确估值」，**不要用别的商品猜**

### 规则 2：效率统一用「元 / 100 积分」

```
效率 = 收益 ÷ 所需积分 × 100
```

例：收益 4.0 元、需要 50 分 → 4.0 ÷ 50 × 100 = **8.00 元/100积分**

**所有券都换算成这个单位再排序**，否则贵的券会排在前面，结论是错的。

### 规则 3：这三类不要估值

- 实物周边（键盘、鼠标、玩偶）→ 标「无法估值（非餐品）」
- 「指定小食任选」这类没指定具体餐品的 → 标「无法估值（未指定餐品）」
- 菜单里找不到对应餐品的 → 标「无法估值（菜单无此餐品）」

**宁可标无法估值，也不要编一个数字。**

### 规则 4：蒸发率

```
蒸发率 = 已过期积分 ÷ 累计获得积分 × 100%
```

## 输出格式（照这个结构）

### 一、体检结果

> 你累计拿到 **5,358 分**，其中 **2,355 分已经过期清零** —— 占 **44%**。
> 可用余额 556 分，本月还有 166 分到期。

（如果蒸发率 > 30%，加一句：这个比例不低，积分最狠的地方不是贬值，是不会提醒你正在贬值。）

### 二、兑换排行（元/100积分，从高到低）

| # | 券 | 积分 | 原价 | 收益 | 效率 |
|---|---|---|---|---|---|
| 1 | 18.8元麦辣鸡腿汉堡两件套 | 50 | 22.8 | 4.20 | **8.40** |
| 2 | 22.8元2份麦辣鸡腿堡 | 500 | 58.0 | 35.20 | 7.04 |

（只列有估值的，最多 8 条。末尾补一句：另有 N 件无法估值，原因是……）

**如果第一名和最后一名的效率差 2 倍以上**，加一句：
> 注意：越贵的券不一定越划算。积分单价贵 16 倍的券，效率可能只有小券的 43%。

### 三、本月到期的怎么花

给定到期积分（假设 166 分），按效率从高到低**贪心**安排，直到装不下：

> 本月到期 166 分，这样花最省：
> - 5.9元香芋派券 × 3 → 花 150 分，省 7.80 元
> - 剩 16 分凑不成整券，可以留到下月

⚠️ **这是近似方案，不是数学最优。** 要精确解用完整版的 `--live` 命令。
如果用户要求"绝对最优"，就说明这一点，不要假装已经是最优。

### 四、抽奖要不要抽

先看 `query-lottery-info` 返回里**有没有每项奖品的中奖概率**。

**有概率**：
```
单次期望收益 = Σ(奖品价值 × 概率)
抽奖效率 = 单次期望收益 ÷ 单次消耗积分 × 100
```
然后和兑换第一名的效率比：
- 抽奖效率 > 兑换效率 × 1.3 → 「偶尔抽可以」
- 抽奖效率 < 兑换效率 → 「别抽，直接换」

**没有概率**（多数情况）：
不要说"期望值是 X"。诚实地说：

> 官方没公布逐档概率，所以算不出精确期望值。
> 但可以从两个角度看：
> - 单次消耗 24 分，相当于 X 张券的积分
> - 你历史上抽到的券，最后用掉了几张？券没用掉 = 白抽
>
> 如果历史兑现率低，抽奖的真实收益会比账面数字低不少。

## 边界（这些话每次都要说）

1. **不替用户兑换、下单、抽奖** —— 只读，所有操作要他自己在 App 里完成
2. 估算基于菜单原价，**实际价格以麦当劳 App 为准**
3. 上面标了「无法估值」的券，是真的算不出来，不是漏了

## 已知局限（用户问起时才说，不要主动啰嗦）

| 项 | 局限 |
|---|---|
| 券名匹配 | AI 做模糊匹配，可能不如程序精确；不同时间跑结果可能有细微差异 |
| 清仓方案 | 贪心近似，不是背包最优解 |
| 抽奖概率 | 官方不公布时只能定性判断，给不出精确 EV |
| 菜单时段 | 10:30 前只有早餐菜单，正餐券会大面积「无法估值」；遇到就说「建议 10:30 后再跑」 |
